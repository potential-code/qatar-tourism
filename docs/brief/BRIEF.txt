
Qatar Tourism AcademyMockup Development Brief
Prepared by Potential.com for the design and development team
Version 1.0  |  26 October 2026  |  Customer demonstration using fictional data
Build objective
Build an attractive, animated Qatar Tourism branded Academy demonstration that connects public registration, personalised learning, hybrid training, trainer assessment and Academy administration. The customer must be able to explore the experience and see how an action in one role updates the other roles and the reporting.
This is a self-contained implementation brief. The development team should not need to attend the customer meetings or read the email threads. Use the supplied page copy, fictional curricula, sample scenarios, data plan and acceptance criteria as the starting specification.
Customer context
Qatar Tourism’s Service Excellence Academy described more than 80,000 learners across two learning management systems and four learning groups: Qatar Host, Qatar Specialist, tour guides and desert safari guides. Existing systems already support many learning functions. The opportunity is to connect the experience, reduce manual coordination and demonstrate controlled access for external trainers.
Priorities raised on 21 October were a unified entry point, CRM-linked registration, single sign-on, booking and rescheduling, content maintenance, assessment, certification and reporting. External trainer visibility and exports are constrained by the customer’s IT policies. Virtual classroom integration and hosting also require IT review.
Customer trial request and expanded scope
Eiman requested Program A with stages, levels and certification; Program B with one learning-path stage and no certification; and complete learner, external trainer and administrator journeys. On 26 October she confirmed that work should proceed using the existing requirements while Karolanne is away.
Rawzaba has expanded the mockup to include an animated public homepage, open registration, pre and post assessments, AI path recommendations, text and voice role-play, video and SCORM content, trainer scheduling, 1,200 fictional learners and AI-assisted analytics. These are demonstration design requirements, not a claim that Qatar Tourism has approved a production specification.
Non negotiable outcome
Deliver a coherent, responsive, stateful demonstration. Every primary button must work, open a purposeful flow or clearly identify a simulated capability. No empty dashboards, unrelated stock screens, dead cards, lorem ipsum or invented production claims.

8  Interactive content and assessment bank
SCORM and Articulate demonstration
Provide at least one functioning sample SCORM 1.2 or SCORM 2004 package exported from an authorised authoring tool or built as a standards-compatible sample. Articulate is an authoring tool; its export format determines player support. The interface must identify the supported format accurately. A branching HTML preview alone must be labelled as a preview, not as verified SCORM integration.
Player controls: launch, resume, restart with confirmation, captions where available, close and return to path. Persist completion, success status, score, session time and resume/suspend data. Map package outcomes to the unit and enrolment. Demonstrate that closing and reopening resumes the activity and that a reported pass updates progress once. Keep the player keyboard accessible and isolate package code appropriately.
Sample branching interaction
Visitor: “Our planned activity is unavailable and we only have two hours.” Choices: A — Promise the original activity anyway; B — Ask about interests and accessibility needs, then offer two verified alternatives; C — Tell them to search online. Correct: B. Feedback: “You clarified the need and offered realistic choices.” Continue to choosing an option and confirming the next step. Record choices and final score.

Scoring and feedback
Score five criteria from 0–4: empathy and professionalism; discovery questions; clarity; accuracy and boundaries; solution and follow-through. Total out of 20 converts to 100. Each criterion must include one evidence excerpt from the conversation and a concise improvement suggestion. Do not score accent or demographic characteristics.
Example: 16/20 = 80/100. Strength: You acknowledged the visitor’s frustration. Improve: Verify availability before promising an alternative. Suggested retry: Ask one question about timing before presenting options. Display attempt history and best/latest score separately. AI practice is formative; trainer marks and programme rules control certification.
If using scripted demo responses, label “Simulated AI practice”. If a live model is used, confine it to the approved scenario and demo content, handle failures gracefully and never present invented official policies as facts.

Session rubric: preparation 20 points; communication 30; practical application 30; professionalism 20. Demo pass threshold is 70/100. Absence cannot automatically become a pass. A cancelled session must not unlock attendance or completion requirements.
Rescheduling and cancellation

Preserve enrolled learners, flag conflicts and allow them to confirm or select another eligible session. Cancellation retains history, releases the active reservation and offers alternatives; it does not mark the learner completed.
After confirmation, update the session once, create one notification per affected active RSVP, update My sessions, log the event and show the success modal specified in section 11. Retrying the action must not send duplicate messages. Waitlisted learners receive the appropriate separate update if their queue is affected.

Metric definitions
Unique learners = distinct learner IDs in the selected cohort. Enrolments = programme registrations, allowing more than one per learner. Active learner = at least one recorded learning activity in the last 30 days as of the demo reporting date. Completion rate = completed enrolments divided by eligible enrolments in the same filtered cohort. Attendance rate = attended or late records divided by due non-cancelled session bookings. Certificate count = issued, non-revoked A certificates.
