# Functional versus simulated capabilities

Brief §1 and Rawzaba's email ask for a clear list of what is real and what is simulated, and for
every simulated capability to be labelled in the UI.

- **Functional** means real and stateful in the browser. The action writes to the demo database
  that this browser keeps in IndexedDB, other roles in the same browser and the reports see the
  change, and a reset restores the snapshot. There is no server: see `docs/DEVIATIONS.md`.
- **Simulated** means the behaviour is scripted or a demonstration adapter. Results are still
  stored and still derived from the seeded data where relevant, but no external service is
  called and no AI model runs.

Every data screen also shows the **Demo data** indicator (`DemoBadge`), and the public footer
says: "Demonstration environment. All learner and training data is fictional."

| Sign in (Learner, Trainer, Academy admin modes)                                   | Functional | Mode changes the interface only. It never grants a role. The trainer mode says "Choosing this mode does not grant trainer access."                                                               |
| Forgot password                                                                   | Simulated  | A reset link is generated. The page is labelled **"Demo email"** and explains that example.com addresses have no real inbox                                                                      |
| SSO ("Continue with Qatar Tourism account", "Continue with organisation account") | Simulated  | Buttons tagged **"Simulated"**. The dialog is labelled **"Simulated connection"**. Each signs in as one fixed seeded learner. No identity provider is contacted. Audited as `auth.sso_simulated` |
| CRM registration and synchronisation                                              | Simulated  | Not connected. Integration settings shows state **"Not connected"** with the reason                                                                                                              |
| Three-step profile wizard, draft resume                                           | Functional | Stored per learner. Drives path assignment rules                                                                                                                                                 |
| Program A enrolment from the public site                                          | Functional | Explicit choice. Confirms under the demo approval rule shown (read-only) in Programme management. Existing B progress is kept                                                                    |
| Demo toolbar (role switching)                                                     | Functional | Admin only. Signs in as the seeded personas, trainers and admin in the same browser, so each role sees the others' changes. Clearly marked as the demo toolbar                                   |

## What is never claimed

- No email is described as delivered. Seeded and generated demo emails are always in the
  `simulated` state.
- No identity is described as authenticated by Qatar Tourism.
- No AI model is called anywhere in the application.
- The certificate is not a guide licence, permit or official qualification.
